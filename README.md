# 数据资产与生命周期治理平台

面向数据资产编目、冷热分层、生命周期管理、血缘追踪与合规治理的统一数据治理平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/WorkbenchView.vue|tsx  全部模块共享工作台
│   ├── src/data/modules.ts              18个业务模块配置
│   ├── src/api/              统一请求封装
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/resource.py  通用查询/导出/登记/动作接口
│   ├── app/services/<key>.py    每个模块独立领域逻辑
│   ├── app/services/base.py     共享服务骨架
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 预热回迁的调度期限凭据

预热回迁不再只登记「过期策略」原文，而是把冷存储侧的对象就绪证据与回迁调度期限关联起来：

- **受理**（`POST /api/hot_prefetch/acceptances`）：按受理时刻与**当时**的策略版本算出一个
  绝对 `deadline`，连受理实际时间、策略版本、窗口一起冻结在受理台账里，返回凭据 `token`。
  旧受理即便后来默认期限调整，也保持原策略版本与期限，可回查当时的适用规则。
- **就绪证据**（`POST /api/cold_storage/readiness`）：冷存对象就绪时在冷存储侧登记，
  记录对象 URI、校验摘要与就绪时刻；重复确认不会改写首次就绪时刻。
- **执行**（`POST /api/hot_prefetch/acceptances/{token}/execute`）：先核对同一冷存对象的
  就绪证据，再比较「就绪时刻」与「调度期限」：就绪时刻必须严格早于期限才发读取凭据；
  恰好同一刻视为队列到期先行，判为过期；就绪证据属于别的对象时拒读。
  过期判断只看就绪时刻，不看提交先后，所以期限前已就绪的对象不会因为确认流程走完得晚而作废。
- **幂等**：同一凭据重复提交返回首次读取结果，读取次数与读取对象不变；实际读取在冷存侧
  再落一份读取台账（`GET /api/cold_storage/object_reads`），过期项不会留下读取记录。

端到端场景（09:59 受理撞上 10:00 到期、10:03 的新请求、期限调整后重开旧任务、重复提交）：

```bash
cd backend && .venv/bin/python verify_prefetch_credentials.py
```

## 约定

- 全部模块共享`frontend/src/views/WorkbenchView.vue|tsx`和一套资源路由。
- 每个模块仍保留独立`backend/app/services/<模块>.py`；纯前端保留
  `frontend/src/domain/<模块>.ts`，用于承载真实业务差异并维持36题位容量。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
